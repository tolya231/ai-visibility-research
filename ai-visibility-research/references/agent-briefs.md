# Постановки для агентов

Подставь `{SITES}` (URL + что за продукт), `{NICHE}`, `{QUERIES}`, `{OUT}` (папка результатов), `{DATE}`. Агент знает только то, что в постановке: давай пути к файлам, а не пересказ выводов. Все агенты пишут результат в файл и возвращают выжимку до 30–40 строк.

## Кабинетный обзор → `01-literature.md`

Веб-поиск на русском и английском (свежее 12 месяцев, дата у каждого источника): как Алиса AI / Нейро выбирает источники, справка Яндекс Вебмастера, YandexAdditional, отчёт «Видимость в Алисе AI»; GigaChat, DeepSeek, ChatGPT (OAI-SearchBot, Bing), Perplexity, Google AI Overviews; контентные факторы (answer-first, подборки «лучшие X», цифры, свежесть, schema, llms.txt); измерение; кейсы с цифрами; что не работает и санкции. Каждый вывод — [О]/[И]/[П] и ссылка с датой. В конце чек-лист по эффекту/трудозатратам, «не делать», «не удалось подтвердить». Сверься с `references/knowledge.md` и отметь, что изменилось.

## Живая выдача и Алиса → `02-live-alice-and-demand.md` (один браузерный агент)

Chrome пользователя по CDP. Для `{QUERIES}` (по ~10 на нишу: разговорные «посоветуй…» и обычные + 2–3 брендовых): `ya.ru/search/?text=…&lr=213` → тип блока «Быстрый ответ ИИ» (с источниками / генеративный / нет), кого рекомендует, процитированные домены и URL (сохранить сырые JSON), топ-10 органики, позиция наших сайтов; `site:` для каждого домена. Затем Вордстат: широкое и точное по 15–25 вопросным/рекомендательным фразам на нишу, период записать. Выводы: частотная таблица цитируемых доменов по нишам, где у сайтов шанс. Если CDP висит дважды по 30 с — остановиться.

## Кабинеты и другие ассистенты → `05-webmaster-bing-assistants.md` (тот же браузерный агент, после предыдущего)

Только чтение. Вебмастер: путь к «Видимость сайта в Алисе AI», цифры, страницы в поиске и исключённые с причинами, ИКС. Bing: `site:домен`, доступность bing.com/webmasters. Ассистенты по приоритету РФ: GigaChat, чат Алисы AI (отдельно от блока в выдаче), DeepSeek (с поиском) — все запросы; ChatGPT, Perplexity — по остаточному принципу. По 4 запроса на сайт, новый чат на каждый; назван ли сайт, кто рекомендован, источники; каким поиском пользуется ассистент. Логин/капчу не обходить.

## Аудит сайтов → `03-site-audit.md`

curl без браузера, сверка с исходниками (если есть). По каждому сайту таблица «проверка | факт | вердикт | действие с путём к файлу»: robots и ответ для ~17 UA ботов, текст без JS, мета, schema.org (валидность JSON-LD), answer-first, таблицы/FAQ/цифры/даты, бренд-сущность и путаница имён, расхождения цен, «О проекте», коды всех URL из sitemap, совпадают ли исходники с продом. Ничего не менять.

## Сверка утверждений → `04-factcheck.md`

Список утверждений (из статьи / ответа нейросети пользователя). По каждому — первоисточник (кто, когда, выборка, методика), вердикт: верно / частично / неверно / не подтверждено / не применимо к РФ; уровень доказательности. Отдельно: что важно для сайтов пользователя, что стоит изучить дальше.

## Эксперимент: процитированные vs нет → `06-exp-cited-vs-not.md`

Из сырых данных `02-…` взять запросы с ответом ИИ с источниками; скачать страницы топ-10 (curl, HTML в отдельную папку, Python с `-I`), посчитать признаки (позиция, answer-first, h2-вопросы, таблицы, списки, FAQ, JSON-LD, даты, объём, слова запроса в начале title, тип страницы, доля цифр), сравнить cited vs not-cited (медианы, доли, Фишер/Манн–Уитни), распределение позиций цитат. Честно про размер выборки. Разобрать страницы наших сайтов.

## Браузерные эксперименты → `07-exp-live.md` (один агент, одно окно, без аккаунта и с аккаунтом, RU-IP)

1) Стабильность: 5 запросов × 4 прогона, пересечение источников. 2) Длинный сценарный запрос vs короткий по той же теме (5 пар). 3) Регион: `lr=213` vs `lr=2` vs `lr=54`. 4) Чат Алисы (`alice.yandex.ru` / `ya.ru/alice`) vs блок в выдаче. 5) Глубина: для 5 запросов снять органику до 30-й позиции и проверить, есть ли среди цитат страницы 11–30.

## Критики → `09-critique-*.md`

Три независимых агента, каждому — пути ко всем файлам `{OUT}`, но не итоговые выводы оркестратора:
- **Методолог**: какие выводы не следуют из данных (размер выборки, один прогон, корреляция ≠ причина, смещение отбора запросов, персонализация из-за залогиненного браузера), что перемерить и как.
- **Источники и цифры**: каждая цифра в `00-REPORT.md` и `site-*.md` → первоисточник; пересказы, устаревшее, неверные даты, перепутанные метрики (аудитория vs охват, доля запросов vs доля трафика).
- **Адвокат дьявола**: что не применимо к РФ / к нише / к типу продукта (Telegram-бот, сервис, контентный сайт); альтернативные объяснения наблюдений; какие рекомендации могут навредить или потратить время зря.
Каждый возвращает список замечаний с серьёзностью (критично / важно / мелочь) и конкретной правкой.

## Перепроверка → `10-recheck-*.md`

После критиков: переснять спорное в чистом контексте с RU-IP (базовые запросы 1 прогон × топ-20 + частотные нейтральные запросы из Вордстата), ассистентам — вопросы о содержимом сайта без домена (отдельное окно), без браузера — то, что критики считают артефактом (сеть, логи). В отчёте — «что подтвердилось / что поменялось» относительно прежних файлов.
